1. Abstract

CaS (Cleaning as a Service) is a comprehensive web platform for managing cleaning services. This document describes the technical architecture, APIs, and core functionalities of the system, providing complete documentation for developers and integrators.

2. Introduction

In today's digital era, managing cleaning services requires robust and user-friendly software solutions. CaS addresses this need by providing a complete web platform that enables:

  • Efficient management of appointments and services
  • Real-time equipment and resource monitoring
  • Employee and work schedule management
  • Simplified customer interaction
  • Detailed reporting and analysis

5. Database Schema

5.1 Main Tables

  • users - System users (ADMIN, MANAGER, EMPLOYEE, CUSTOMER)
  • locations - Cleaning locations with GPS coordinates
  • services - Available services (carpets, cars, clothing)
  • equipment - Equipment with wear monitoring and maintenance
  • resources - Resources/consumables (detergents, chemicals)
  • inventory - Stock per location with automatic alerts
  • orders - Orders with transport and recurring scheduling

5.2 Linking Tables

  • service_resources - Required resources per service
  • location_services - Available services per location
  • order_resources - Resources consumed per order

6. Roles and Permissions

6.1 Administrator (ADMIN)

  • Complete user management
  • Location and service configuration
  • Global resource management
  • Access to all reports and statistics

6.2 Employee

  • View and update tasks
  • Report issues
  • Transport management
  • Material consumption recording

6.3 Customer

  • Service scheduling
  • Order tracking
  • History viewing
  • Feedback provision

7. Security

The system implements the following security measures:

  • JWT Authentication with refresh tokens
  • Sensitive data encryption
  • API rate limiting
  • Input validation and data sanitization
  • Logging and audit trail

8. Monitoring and Logging

The system implements extensive logging for:

  • User activity
  • Errors and exceptions
  • System performance
  • API access

Logs are stored in structured format and can be accessed through the admin interface.

9. Deployment

The application can be deployed using:

  • Docker containers
  • Kubernetes for orchestration
  • Automated CI/CD pipeline
  • Monitoring and alerting
